# Lemify API — Mensagens (WhatsApp)

> Envio de mensagens de texto e mídia pelo WhatsApp para qualquer número.

Base URL: https://api.lemify.com.br

## Autenticação

Token do canal WhatsApp em `Authorization: Bearer <TOKEN_DO_CANAL>` (Canais > WhatsApp > Token da API).

Erros vêm como JSON `{ "error": "mensagem" }`. 401 = credencial ausente/inválida, 403 = sem permissão/escopo ou plano sem acesso à API, 429 = limite de requisições (respeite `Retry-After`).

## Endpoints

### POST /v1/messages/send

**Envia mensagem via API externa**

Endpoint para integração externa. Permite enviar mensagens de texto ou mídia
para qualquer número de WhatsApp sem necessidade de um ticket existente.

**Autenticação:** Clique em "Authorize" e insira o token do canal WhatsApp.
O token pode ser obtido na seção "Canais > WhatsApp > Token da API" do sistema Lemify.

**Importante:** O número deve ter WhatsApp ativo e a conexão deve estar CONNECTED.

Corpo (application/json):
- `number` (string, obrigatório): Número do WhatsApp com DDD (apenas números); ex.: "5511999999999"
- `body` (string): Texto da mensagem; ex.: "Olá! Esta é uma mensagem de teste via API."
- `createTicket` (boolean): Se true, cria um ticket e salva a mensagem no histórico do chat. Se false (padrão), apenas envia a notificação sem criar ticket.; padrão: false

Também aceita multipart/form-data:
- `number` (string, obrigatório): Número do WhatsApp com DDD (apenas números, sem formatação); ex.: "5511999999999"
- `body` (string): Texto da mensagem; ex.: "Olá! Esta é uma mensagem de teste via API."
- `medias` (string (binary)[]): Arquivos de mídia para envio (imagens, vídeos, documentos, áudios)
- `createTicket` (boolean): Se true, cria um ticket e salva a mensagem no histórico do chat. Se false (padrão), apenas envia a notificação sem criar ticket.; padrão: false

Respostas:
- 200: Mensagem enviada com sucesso
- 400: Erro de validação ou envio
- 401: Token de autenticação ausente ou inválido
- 404: Conexão WhatsApp não encontrada
- 429: Limite de envio excedido (rate limit)
- 500: Erro interno no envio

Resposta 200 (objeto com):
- `mensagem` (string): ex.: "Mensagem enviada com sucesso"

```bash
curl -X POST "https://api.lemify.com.br/v1/messages/send" \
  -H "Authorization: Bearer $LEMIFY_CHANNEL_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"number":"5511999999999"}'
```

# Lemify API — Agenda

> Agendamentos: listar, consultar, criar, alterar, excluir, horários disponíveis e conflito de horário.

Base URL: https://api.lemify.com.br

## Autenticação

Chave de API da empresa em `Authorization: Bearer lmf_...` (ou `X-API-Key`), escopos `agenda:read` / `agenda:write`. Gere em Configurações > Chaves de API.

Erros vêm como JSON `{ "error": "mensagem" }`. 401 = credencial ausente/inválida, 403 = sem permissão/escopo ou plano sem acesso à API, 429 = limite de requisições (respeite `Retry-After`).

## Endpoints

### GET /v1/agenda

**Lista agendamentos**

Lista agendamentos com paginação (100 por página). A chave é da empresa e enxerga todas as filiais;
use `branchIds` para filtrar. Escopo exigido: `agenda:read`.

Parâmetros:
- `date` (query, string (date)): Data (YYYY-MM-DD)
- `status` (query, string): valores: pending, confirmed, cancelled, completed
- `professionalId` (query, integer)
- `userId` (query, integer)
- `searchParam` (query, string): Busca por nome/telefone do cliente
- `pageNumber` (query, integer): padrão: 1
- `branchIds` (query, string): Filiais separadas por vírgula, ex. 1,2

Respostas:
- 200: Lista de agendamentos
- 401: Token de autenticação ausente ou inválido
- 403: Acesso negado - permissões insuficientes

Resposta 200 (objeto com):
- `agendas` (object[])
  - `id` (integer): ex.: 123
  - `title` (string)
  - `customerName` (string): ex.: "Maria Silva"
  - `customerPhone` (string): ex.: "5511999999999"
  - `customerEmail` (string)
  - `date` (string (date)): ex.: "2026-10-20"
  - `time` (string): ex.: "14:00:00"
  - `endTime` (string): ex.: "14:30:00"
  - `duration` (integer): Duração em minutos
  - `service` (string)
  - `status` (string): valores: pending, confirmed, cancelled, completed
  - `notes` (string)
  - `location` (string)
  - `meetLink` (string)
  - `recurrence` (string): valores: none, daily, weekly, monthly
  - `professionalId` (integer)
  - `userId` (integer)
  - `contactId` (integer)
  - `branchId` (integer)
  - `createdAt` (string (date-time))
  - `updatedAt` (string (date-time))
- `count` (integer)
- `hasMore` (boolean)

```bash
curl -X GET "https://api.lemify.com.br/v1/agenda" \
  -H "Authorization: Bearer $LEMIFY_API_KEY"
```

- `professionalId` (integer)
- `userId` (integer)
- `contactId` (integer)

Respostas:
- 201: Agendamento criado
- 400: Dados inválidos, filial inválida ou horário indisponível/em conflito
- 401: Token de autenticação ausente ou inválido

- `title` (string)
- `customerName` (string): ex.: "Maria Silva"
- `customerPhone` (string): ex.: "5511999999999"
- `customerEmail` (string)
- `date` (string (date)): ex.: "2026-10-20"
- `time` (string): ex.: "14:00:00"
- `endTime` (string): ex.: "14:30:00"
- `duration` (integer): Duração em minutos
- `service` (string)
- `status` (string): valores: pending, confirmed, cancelled, completed
- `notes` (string)

- `createdAt` (string (date-time))

# Lemify API — CRM (negociações)

> Negociações (deals), pipelines, etapas e motivos de ganho/perda; criação idempotente por externalId e sincronização por updatedSince.

Base URL: https://api.lemify.com.br

## Autenticação

Chave de API da empresa em `Authorization: Bearer lmf_...` (ou `X-API-Key`), escopos `crm:read` / `crm:write`. Gere em Configurações > Chaves de API.

Erros vêm como JSON `{ "error": "mensagem" }`. 401 = credencial ausente/inválida, 403 = sem permissão/escopo ou plano sem acesso à API, 429 = limite de requisições (respeite `Retry-After`).

## Endpoints

### GET /v1/pipelines

**Lista pipelines e etapas**

Use para descobrir os ids de pipeline e etapa (`stageId`). Etapas ocultas não aparecem. Escopo exigido: `crm:read`.

Respostas:
- 200: Pipelines com suas etapas
- 401: Token de autenticação ausente ou inválido
- 403: Acesso negado - permissões insuficientes

Resposta 200 (lista de objetos com):
- `id` (integer): ex.: 1
- `name` (string): ex.: "Funil Comercial"
- `position` (integer): ex.: 0
- `isDefault` (boolean): ex.: true
- `stages` (object[])
  - `id` (integer): ex.: 12
  - `name` (string): ex.: "Qualificação"
  - `position` (integer): ex.: 0
  - `closureType` (string): valores: won, lost; ex.: null

```bash
curl -X GET "https://api.lemify.com.br/v1/pipelines" \
  -H "Authorization: Bearer $LEMIFY_API_KEY"
```

### GET /v1/deal-reasons

**Lista motivos de ganho/perda**

Ids para `dealReasonId`. Escopo exigido: `crm:read`.

Respostas:
- 200: Motivos
- 401: Token de autenticação ausente ou inválido
- 403: Acesso negado - permissões insuficientes

Resposta 200 (lista de objetos com):
- `id` (integer): ex.: 4
- `name` (string): ex.: "Condição comercial"
- `type` (string): valores: won, lost; ex.: "won"

```bash
curl -X GET "https://api.lemify.com.br/v1/deal-reasons" \
  -H "Authorization: Bearer $LEMIFY_API_KEY"
```

### GET /v1/deals

**Lista negociações**

Lista paginada (até 100 por página). Para sincronizar, envie `updatedSince` com o maior
`updatedAt` já recebido: a ordem passa a ser por `updatedAt` crescente. Sem `status`, a
lixeira fica de fora. Escopo exigido: `crm:read`.

Parâmetros:
- `updatedSince` (query, string (date-time))
- `status` (query, string): valores: open, won, lost
- `pipelineId` (query, integer)
- `stageId` (query, integer)
- `contactId` (query, integer)
- `source` (query, string): Plataforma de origem (whatsapp, instagram, manual, lead_form, api...)
- `externalSource` (query, string)
- `externalId` (query, string)
- `pageNumber` (query, integer): padrão: 1
- `limit` (query, integer): padrão: 50; máx.: 100

Respostas:
- 200: Negociações
- 400: Parâmetro inválido
- 401: Token de autenticação ausente ou inválido
- 403: Acesso negado - permissões insuficientes

Resposta 200 (objeto com):
- `deals` (object[])
  - `id` (integer): ex.: 456
  - `name` (string): ex.: "Pedido 1042"
  - `amount` (number): ex.: 1500
  - `status` (string): valores: open, won, lost, trashed; ex.: "open"
  - `description` (string): ex.: "Cliente interessado no plano anual"
  - `items` (object[])
  - `lostReason` (string)
  - `nextStep` (string): ex.: "Enviar proposta comercial"
  - `leadSource` (string): Origem de marketing em texto livre; ex.: "Google Ads"
  - `source` (string): Plataforma de origem: whatsapp, instagram, facebook, webchat, manual, lead_form, api...; ex.: "api"
  - `externalSource` (string): ex.: "erp"
  - `externalId` (string): ex.: "1042"
  - `score` (integer): ex.: 85
  - `scoreLabel` (string): ex.: "hot"
  - `closingDate` (string (date-time))
  - `deliveryDate` (string (date-time))
  - `wonAt` (string (date-time))
  - `lostAt` (string (date-time))
  - `contact` (object)
  - `user` (object)
  - `pipeline` (object)
  - `stage` (object)
  - `dealReason` (object)
  - `createdAt` (string (date-time))
  - `updatedAt` (string (date-time))
- `count` (integer)
- `hasMore` (boolean)

```bash
curl -X GET "https://api.lemify.com.br/v1/deals" \
  -H "Authorization: Bearer $LEMIFY_API_KEY"
```

### POST /v1/deals

**Cria uma negociação**

Cria o deal na etapa informada; automações da etapa e eventos de conversão do Meta disparam
como no painel. Com `externalId`, a chamada é idempotente: se já existir um deal com o mesmo
`externalSource` + `externalId`, ele é devolvido com status 200. Escopo exigido: `crm:write`.

Corpo (application/json):
- `name` (string, obrigatório): até 255 caracteres; ex.: "Pedido 1042"
- `stageId` (integer, obrigatório): ex.: 12
- `pipelineId` (integer): Opcional; se vier, precisa ser o pipeline da etapa; ex.: 1
- `amount` (number): Ignorado quando o deal tem items: o valor passa a ser a soma de price × quantity; ex.: 1500
- `status` (string): valores: open, won, lost; ex.: "open"
- `contactId` (integer): ex.: 345
- `userId` (integer): Responsável (usuário da empresa); ex.: 7
- `dealReasonId` (integer): Motivo de ganho/perda (veja /v1/deal-reasons)
- `description` (string): até 10000 caracteres; ex.: "Cliente interessado no plano anual"
- `items` (object[])

  - `id` (integer): Produto/serviço cadastrado na empresa; ex.: 10
  - `name` (string, obrigatório): ex.: "Plano Anual"

  - `quantity` (number): padrão: 1; ex.: 1

- `closingDate` (string (date)): ex.: "2026-12-01"
- `deliveryDate` (string (date))
- `nextStep` (string): até 255 caracteres; ex.: "Enviar proposta comercial"
- `leadSource` (string): até 255 caracteres; ex.: "Google Ads"

- `externalId` (string): Id no sistema de origem; torna o POST idempotente; até 128 caracteres; ex.: "1042"

Respostas:
- 200: Já existia (mesmo externalSource + externalId)
- 201: Criado
- 400: Dados inválidos, id de outra empresa ou etapa oculta
- 401: Token de autenticação ausente ou inválido
- 403: Acesso negado - permissões insuficientes

Resposta 200 (objeto com):
- `id` (integer): ex.: 456

  - `quantity` (number): padrão: 1; ex.: 1

### PUT /v1/deals/{dealId}

**Atualiza uma negociação**

Envie só os campos a alterar. Escopo exigido: `crm:write`.

Parâmetros:
- `dealId` (path, integer, obrigatório)

Corpo (application/json):
- `name` (string, obrigatório): até 255 caracteres; ex.: "Pedido 1042"
- `stageId` (integer, obrigatório): ex.: 12
- `pipelineId` (integer): Opcional; se vier, precisa ser o pipeline da etapa; ex.: 1
- `amount` (number): Ignorado quando o deal tem items: o valor passa a ser a soma de price × quantity; ex.: 1500
